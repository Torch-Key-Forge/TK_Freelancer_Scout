# Privacy and Permissions

## Data accessed

In its initial mode, Freelancer Scout accesses active project-listing information needed to identify and assess possible work. If authenticated identity is required by the API, the application may also request the minimum profile-view permission needed to confirm the authorized account.

## Data use

Retrieved information is used only for Torch & Key's internal opportunity review and project-intake decisions. Freelancer data is not sold, licensed, redistributed, used for advertising, or offered as a separate commercial dataset or service.

## Storage and disclosure

The public sample prints responses to standard output and does not create a persistent datastore. Operators are responsible for keeping any local working material private, access-controlled, and no longer than operationally necessary. This public repository must not contain API responses, receipts, client material, credentials, tokens, or private profile data.

## Credentials

OAuth tokens, client secrets, `.env` files, credential exports, and local configuration are excluded from version control. Credentials must be supplied at runtime from a private local environment and must not be placed in code, issues, pull requests, screenshots, logs, or documentation.

## Permission boundary

The initial application is read-only. It is not authorized to place bids, send or read messages, accept awards, manage milestones, edit projects or contests, modify account data, or perform financial or contractual actions.

No broader capability may be enabled merely because the API or an OAuth scope makes it technically possible. Any future write action requires explicit CJ authorization. Human approval must be specific to the action; recommendations and automated rankings do not count as approval.

## Public-repository boundary

This repository is an informational application home and a minimal read-only example. It intentionally excludes internal Estate doctrine, private control records, evidence receipts, customer data, and operational credentials.

## Questions

Privacy or permission questions should be directed through the public contact channel maintained by the repository owner, Torch-Key-Forge.
